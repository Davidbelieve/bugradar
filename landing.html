// the model

Not heuristics. Actual machine learning.

BugOracle uses a Random Forest classifier trained on the NASA KC1 + PC1 datasets — real defect data from aerospace software. It analyses 21 Halstead complexity and McCabe cyclomatic metrics per function to compute a defect probability score.

The threshold is calibrated at 0.40 (v3 optimised) for high recall catching more real bugs at the cost of occasional false positives. For high-stakes codebases, that's the right tradeoff.

// faq

Common questions

What languages does BugOracle support? ▼

Currently Python only. The Radon library extracts Halstead and McCabe metrics from Python source files. Support for JavaScript and TypeScript is on the roadmap.

How accurate is the defect prediction? ▼

The model achieves 85% AUC-ROC on the NASA KC1 + PC1 test sets. The threshold is tuned at 0.40 for high recall meaning it catches more real bugs, with some false positives. You can always override a blocked merge if you disagree with the prediction.

Does BugOracle read my source code? ▼

BugOracle only extracts numerical complexity metrics from your code it never stores the source code itself. The 21 metric values are sent to the API, scored, and the result is returned. Your code stays in your repo.

Can any team use it, not just my own repo? ▼

Yes. Any team can self-onboard by signing in with GitHub, registering their repo, and adding one YAML file to their workflow. Each repo gets its own isolated API key and scan history.

What happens when I hit the free tier limit? ▼

Scans return a 402 response and the GitHub Action posts a warning on the PR. Merges are not blocked due to quota only due to high defect risk. You can upgrade to Pro at any time for unlimited scans.
